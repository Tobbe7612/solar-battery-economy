## CONFIRMED

- Coordinator-based architecture.
- Event-driven input updates.
- Eight directional power flows.
- Eight accumulated energy flows.
- Persistent Store for energy/money/install date/migration flag.
- Coordinator-level persisted annualization reference.
- Separate total/solar/battery investments.
- Solar/battery annual savings, ROI and payback sensors.
- Battery-origin money split based on cumulative solar/grid battery charge energy.
- Energy sensors use `kWh`, `energy`, `total_increasing`.
- Advanced mode controls detailed money/battery diagnostics.
- Import/export price sensors exist.
- Currency selection exists for SEK/EUR/USD/NOK/DKK/GBP.

## KNOWN ISSUE

### Price availability logic

`_float_state()` returns `0.0` for unavailable/invalid values, while coordinator code checks for `None` before booking money.

This means the intended "skip money booking when price unavailable" branch is inconsistent with the helper's current return contract.

This should be fixed deliberately and tested; it should not be changed as an incidental cleanup.

## NEEDS VERIFICATION

### Options-flow reload order

The options flow reloads the entry before returning the new options data.

This deserves a focused Home Assistant test because it may explain historical behavior where toggling Advanced Mode required another reload.

### Battery-less configuration

The battery power sensor is required by config flow. There is no explicit no-battery mode.

### Flow-card contract

The exact entities consumed by the separate Lovelace flow-card repository are not verifiable from this repository alone.
